# سجل العمل والتنفيذ - Nexus AI VoiceOps

هذا الملف يوضح المسار العملي للمشروع، والقرارات الهندسية التي بُني عليها النظام، حتى يكون المشروع واضحاً عند رفعه على GitHub أو عرضه أمام اللجنة.

## 1. فكرة المشروع

الفكرة الأساسية هي بناء طبقة تشغيل ذكية للبنك، وليست مجرد Chatbot. النظام يستقبل سؤال العميل أو الموظف، يحدد نوع الطلب، يوجهه إلى الوكلاء المناسبين، يرجع إجابة آمنة للعميل، ويعرض للموظف trace كامل يشرح كيف وصل النظام للقرار.

التركيز كان على فجوة مهمة في البنوك: ربط الاستفسارات البنكية، الطلبات التشغيلية، المستندات، الامتثال، وتفسير قرارات الذكاء الاصطناعي داخل تجربة واحدة قابلة للعرض.

## 2. ما تم بناؤه

- بوابة دخول بأدوار مختلفة: عميل وموظف.
- Customer Portal يعرض خدمات بنكية حقيقية بشكل مبسط وآمن.
- Employee Workspace يعرض طلبات العملاء، الوثائق، ردود الوكلاء، trace، audit، وقرارات الموظف.
- Backend Node.js يحوي منطق التحليل والبيانات الصناعية وسير العمل.
- Synthetic banking dataset يحتوي عملاء، رواتب، حسابات، قروض، KYC، بطاقات، مستفيدين، معاملات، ووثائق.
- Multi-Agent decision layer يوجه الطلبات إلى وكلاء متخصصين حسب النية.
- فصل واضح بين رد العميل الآمن والشرح الداخلي الخاص بالموظف.
- Workflow لرفع مستندات القرض من العميل وظهورها في صفحة الموظف مع view/download.
- سجل n8n-style automation يوضح كيف يمكن ربط النظام بإيميلات، تنبيهات، PDF، أو أنظمة legacy لاحقاً.
- رابط تشغيل واحد `http://localhost:4173/login`.

## 3. قرارات هندسية مهمة

- عدم لمس Core Banking حقيقي، بل استخدام sandbox data layer آمن.
- استخدام JSON data store للعرض السريع بدلاً من قاعدة بيانات ثقيلة، حتى يكون المشروع سهل التشغيل على أي جهاز.
- إبقاء منطق الوكلاء في backend حتى لا ينكشف للعميل.
- جعل صفحة العميل لا تعرض reasoning داخلي أو أسماء الوكلاء.
- جعل صفحة الموظف هي مكان الشفافية: agent pipeline، confidence، policy evidence، audit timeline.
- جعل الوثائق مرتبطة بـ `requestId` و `customerId` حتى تظهر للموظف في الطلب الصحيح.
- جعل المشروع يعمل برابط واحد لتسهيل العرض أمام الدكتور.

## 4. الوكلاء داخل النظام

- OrchestratorAgent: يحدد نوع الطلب ويوزع العمل.
- PolicyAgent: يطابق الطلب مع سياسات البنك.
- CreditRiskAgent: يحلل أهلية القرض ونسبة المخاطر.
- FraudAgent: يراقب التحويلات أو السلوك غير المعتاد.
- ComplianceAgent: يفحص KYC والمستندات والامتثال.
- PayrollOpsAgent: يحلل مشاكل الرواتب والاستثناءات.
- AccountDataAgent: يقرأ بيانات الحساب والعميل من sandbox.
- CustomerSafetyAgent: يحوّل الرد إلى صيغة آمنة للعميل.
- EvaluatorAgent: يقرر هل النتيجة جاهزة أو تحتاج human review.

## 5. بيانات العرض الصناعية

تم تجهيز بيانات عملاء متنوعة لاختبار النظام:

- عميل لديه مشكلة راتب بسبب عدم تطابق رقم الحساب.
- عميل مؤهل مبدئياً لقرض مع طلب مستندات.
- عميل عالي المخاطر يمكن رفض طلبه بناء على السياسة.
- حالة يمكن أن تشغل FraudAgent بسبب تحويل غير معتاد.
- عميل VIP لديه طلب معقد يتطلب سياسة وتفسير.

الهدف من هذه البيانات هو إظهار أن النظام لا يرد عشوائياً، بل يتصرف بناءً على حالة العميل والبيانات المتوفرة.

## 6. نقاط قوة المشروع في العرض

- ليس Chatbot فقط؛ هو Banking Operations Layer.
- يوجد فصل بين customer-safe response و internal employee reasoning.
- يوجد trace قابل للتدقيق لكل قرار.
- يوجد مستندات وطلبات وقرارات، وليس مجرد نصوص.
- يدعم العربية والإنجليزية.
- يمكن توسيعه لاحقاً إلى قاعدة بيانات حقيقية، n8n workflows، OpenAI API، أو أنظمة بنك داخلية.

## 7. كيف أشرح مساهمتي أمام اللجنة

يمكن شرح المشروع بهذه الطريقة:

"بنيت Nexus AI VoiceOps كطبقة تشغيل ذكية للبنك. الفكرة ليست استبدال النظام البنكي، بل بناء sandbox layer فوق بيانات صناعية تحاكي البنك. العميل يرى رد آمن وبسيط، بينما الموظف يرى القرار الكامل، الوكلاء الذين اشتغلوا، الدليل من السياسة، المستندات، وسجل التدقيق. هذا يجعل النظام قابل للفهم والحوكمة، وهو أهم شيء في القطاع البنكي."
